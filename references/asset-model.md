# 资产模型：六类型、层级与登记规约

> ARTEX 资产图的单文件版。侦察阶段和每次登记资产前重读。

## 一、六种资产类型与唯一键

| 类型 | 含义 | 唯一键 | 典型字段 |
|---|---|---|---|
| root_domain | 根域名 | 域名字符串 | ICP 主体、whois |
| subdomain | 子域名 | 主机名+解析记录类型 | A/AAAA/CNAME 记录、归属根域 |
| ip | IP 地址 | IP 字符串 | 开放端口、C 段、归属 |
| service | 网络服务 | URL（http/https）或 ip:port | 标题、状态码、技术栈、favicon |
| app | 移动/客户端应用 | 包名/bundle id | 版本、内嵌 API 域名 |
| endpoint | 接口端点 | url+method | 参数表、是否需认证 |

## 二、包含层级（覆盖度的骨架）

```
endpoint → service → subdomain / ip → root_domain
app → （其内嵌域名）→ subdomain/root_domain
```

覆盖度 = 已测资产 / 范围内资产，两条硬规则：
- **分母只来自 scope.md**：范围外的资产登记了也不进分母（记 out-of-scope）。
- **分子必须有测试事实**：某资产挂了"已测"标记，就必须能在 facts.md 里找到
  对应意图的测试记录，禁止"扫一眼算测过"。

## 三、登记规约（写 assets.md 前）

1. **由你提交原始信息，格式由模板统一**：每行一条，字段齐全的登记，字段缺的
   先侦察补齐再登记（宁缺毋滥）。
2. **追加合并，不覆盖**：同唯一键再次发现时，新信息（新端口/新技术栈/新认证
   方式）追加到该条目的记录里，历史记录保留。
3. **去重优先**：登记前先查账本里有没有（同主机不同大小写、同服务 http/https、
   带不带端口——都是同一条目的变体）。
4. **保守自动扩范围**：只有用户**显式给出**的顶层目标才进 scope.md；侦察中
   发现的新根域/新 C 段**不自动进范围**，记入 assets.md 并在 facts.md 标注
   "疑似关联，待授权确认"。

## 四、检索纪律

- 查资产永远带条件（按类型/按域名后缀/按端口），**禁止无条件全量罗列**——账本
  会越来越大，全量读浪费上下文。
- 需要总览时输出统计行（各类型多少条、已测/未测比例），不输出明细。
